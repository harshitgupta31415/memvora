# Remaining delivery work

This is the development backlog after the connected local MVP. Read [STATUS.md](STATUS.md) for checks that actually passed, [OWNER_SETUP.md](OWNER_SETUP.md) for personal setup, and [PRD.md](PRD.md) for the wider product target. A local implementation or fixture test does not establish that a real external service or hosted release works.

## What can already be demonstrated

The website, protected local API, explicit Windows CLI capture/outbox, original evidence, cited recall, processing recovery, repository-file imports, investigation history/recaps, authored journal, portable handover and read-only MCP are connected. Accepted raw command evidence remains retrievable while summaries are queued or failed. SQLite retains the local workspace across restarts. GitHub import currently works through the existing local `gh` authorization; App connection and optional AI adapters also have isolated fixture coverage.

The current architecture is a TypeScript modular monolith with shared contracts/domain/persistence and separate web, CLI, MCP and worker entry points. Additional independently deployed services are not needed to finish the personal local release.

Private CLI/MCP installation targets version 0.7.0. [CLIENT_INSTALLATION.md](CLIENT_INSTALLATION.md) documents its local tarball, Node requirements, explicit credentials and maintenance. The isolated installed-package acceptance checks an actual failing command, rejected upload, same-ID retry, raw recall and fourteen read-only MCP tools, including synthesis status/history. Windows/Linux and Node 24/26 CI are the release gates; see [STATUS.md](STATUS.md) for actual results.

[Explicit investigation interpretation](SESSION_SYNTHESIS.md) is implemented behind an independent disabled-by-default flag. It supports bounded original attempts/notes, cited unverified claims, durable single-attempt requests, replay, stale results and deletion fences. Loopback fixtures establish the connected flow; a chosen real provider and human usefulness judgments remain unverified.

Retained synthesis history now exposes earlier ready, failed and stale versions through all clients. The website preserves only an unconfirmed submission's scoped UUID/hash across reload in the same tab, with no automatic resubmission. This is separate from a durable command or journal outbox.

[Authored journal recovery](JOURNAL_RECOVERY.md) adds an opt-in bound-current-session CLI queue, offline metadata inspection and exact selected-note retry. It preserves the original prepared identity/body/citations and verifies the saved scope/first authenticated peer before submission. This is separate from command sync and the browser's in-memory note draft. New verification results belong in STATUS; implementation alone is not a claim that response-loss, restart or installed-package acceptance has passed.

## Owner actions versus development

The owner needs to choose and authorize a real GitHub App, optional AI provider and actual MCP host, then perform the real-account checks in [OWNER_SETUP.md](OWNER_SETUP.md). Those choices do not prevent work on packaging, retrieval evaluation, synthesis follow-up or lifecycle controls. Hosting destination/budget and company sharing policy need decisions before those later release gates; they are not prerequisites for the current local demo.
